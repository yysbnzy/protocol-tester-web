# protocol-tester-web 优化方案

> 基于车载协议测试经验（CAN FD、DoIP、SOME/IP、UDS）的深度优化建议
> 评估对象：protocol-tester-web v3.0
> 参考视角：车载协议 fuzz 测试工具设计（如 CANoe、PCAN-UDS、Scapy-Automotive）

---

## 一、当前问题总结（已确认）

| 问题 | 严重程度 | 位置 | 影响 |
|------|----------|------|------|
| `api_tcp_attack` 未实现 | 🔴 高危 | `app.py` L261 | 畸形报文攻击功能完全失效，前端点了没反应 |
| 前端配置硬编码 | 🟡 中 | `config/default.json` vs `config_manager.py` | 合法值/非法值修改不生效，前后端配置不一致 |
| 无测试覆盖 | 🟡 中 | 全仓库 | 回归风险高，改一处坏一处 |
| 无速率限制 | 🟡 中 | `app.py` | 可能被误用造成网络风暴/DoS |
| DoIP 无 Payload | 🟡 中 | `packet_assembler.py` | 只能测头部，无法测诊断消息内容 |
| SOME/IP 无 Payload | 🟡 中 | `packet_assembler.py` | 同上，无法构造完整 SOME/IP 消息 |
| TCP Raw 模式 KeyError 风险 | 🟡 中 | `tcp_manager.py` | 连接字典字段缺失时崩溃 |
| 全局单例无锁 | 🟡 中 | `__init__.py` | 并发场景下状态竞争 |

## 二、核心优化方向

### 2.1 修复 `api_tcp_attack`（最高优先级）

**当前代码**：
```python
@app.route('/api/tcp/attack', methods=['POST'])
def api_tcp_attack():
    ...
    # 这里需要根据packet_data构造畸形报文
    # 暂时返回成功状态
    return jsonify({'success': True, 'message': f'畸形报文发送完成 - {count}次'})
```

**问题**：这个 API 是工具的核心功能之一，但直接返回成功，前端以为发了实际上什么都没做。

**修复方案**：

```python
@app.route('/api/tcp/attack', methods=['POST'])
def api_tcp_attack():
    global tcp_manager, assembler, send_mode_mgr
    if tcp_manager is None:
        tcp_manager = get_tcp_manager(make_logger())
    if assembler is None:
        assembler = get_assembler()
    if send_mode_mgr is None:
        send_mode_mgr = get_send_mode_manager(make_logger())
    
    data = request.get_json()
    conn_id = data.get('conn_id')
    packet_data = data.get('packet_data', {})
    count = int(data.get('count', 1))
    interval = int(data.get('interval', 100))
    mode = data.get('mode', 'socket')
    
    # 1. 获取连接信息
    conn_info = tcp_manager.get_connection_status(conn_id)
    if not conn_info:
        return jsonify({'success': False, 'message': '连接不存在'})
    
    target_ip = conn_info.get('target', '').split(':')[0]
    target_port = int(conn_info.get('target', '').split(':')[1]) if ':' in conn_info.get('target', '') else 80
    
    # 2. 组装畸形报文
    protocol = packet_data.get('protocol', 'TCP')
    fields = packet_data.get('fields', {})
    illegal_fields = packet_data.get('illegal_fields', [])
    
    assemble_result = assembler.assemble(protocol, fields, illegal_fields)
    if not assemble_result.get('success'):
        return jsonify({'success': False, 'message': f'报文组装失败: {assemble_result.get("error")}'})
    
    packet_bytes = bytes(assemble_result.get('packet_bytes', []))
    
    # 3. 发送
    send_result = send_mode_mgr.send(
        protocol=protocol,
        mode=mode,
        target_ip=target_ip,
        target_port=target_port,
        packet_bytes=packet_bytes,
        count=count,
        interval_ms=interval
    )
    
    return jsonify(send_result)
```

**关键设计点**：
- 复用现有的 `assembler` 和 `send_mode_mgr`，不重复造轮子
- 先组装再发送，和前端流程一致
- 支持选择发送模式（socket/raw/npcap/simulate）

### 2.2 统一前后端配置（解决合法值/非法值修改不生效）

**问题根源**：`config/default.json`（项目根目录）和 `backend/core/config/default.json`（后端用）以及 `config_manager.py` 里的硬编码默认值是**三份不同的配置**。前端读一份，后端读另一份，改了一个另一个不变。

**修复方案**：

1. **删除重复配置**：只保留 `config/default.json`（项目根目录），`backend/core/config/` 可以删掉或做成软链接
2. **config_manager.py 改为读取外部文件**：

```python
class ConfigManager:
    def __init__(self, config_dir='config'):
        base_dir = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
        self.config_dir = os.path.join(base_dir, config_dir)
        self.default_config_file = os.path.join(self.config_dir, 'default.json')
        # ... 其余不变
        
    def get_default_config(self):
        # 不再硬编码，从文件读取
        if os.path.exists(self.default_config_file):
            try:
                with open(self.default_config_file, 'r', encoding='utf-8') as f:
                    return json.load(f)
            except Exception as e:
                print(f"[Config] 加载失败: {e}")
        
        # fallback：最小默认配置
        return {
            'protocols': {},
            'settings': {'default_nic': 'Default', 'send_mode': 'simulate', 'send_count': 1, 'send_interval': 100},
            'version': '1.0'
        }
```

3. **前端不再硬编码**：`index.html` 里所有写死的默认值改为从 `/api/defaults` 动态获取

### 2.3 补全 DoIP 和 SOME/IP 的 Payload 支持

**当前问题**：
- DoIP 只构建了 8 字节头部（version + inv_version + payload_type + payload_length=0），没有实际 Payload
- SOME/IP 构建了 16 字节头部，没有 Payload 字段

**车载测试场景**：
- DoIP 需要测诊断消息（如 UDS 0x10 会话控制、0x27 安全访问），Payload 就是 UDS 请求
- SOME/IP 需要测事件订阅、方法调用，Payload 是序列化的数据

**修复方案** — DoIP 添加 Payload：

```python
def _build_doip(self, fields, illegal_fields):
    # ... 现有头部构建 ...
    
    # 添加 Payload 支持
    payload_str = fields.get('payload', '')
    payload_bytes = b''
    if payload_str:
        try:
            if payload_str.startswith('0x'):
                payload_str = payload_str[2:]
            payload_bytes = bytes.fromhex(payload_str.replace(' ', ''))
        except:
            payload_bytes = payload_str.encode('utf-8')
    
    payload_length = len(payload_bytes)
    
    # 更新字段列表
    doip_fields.append({
        'name': 'Payload Length', 
        'value': str(payload_length), 
        'illegal': False
    })
    if payload_bytes:
        doip_fields.append({
            'name': 'Payload', 
            'value': payload_str[:50] + ('...' if len(payload_str) > 50 else ''),
            'illegal': 'payload' in illegal_fields
        })
    
    # 构建完整报文
    packet_bytes = struct.pack('>BBHI', version, inv_version, payload_type, payload_length)
    if payload_bytes:
        packet_bytes += payload_bytes
    
    # ... 返回 ...
```

**SOME/IP Payload** 类似处理，注意 Length 字段需要包含 header + payload 的总长度。

### 2.5 安全加固

**1. 添加请求速率限制**

```python
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

limiter = Limiter(
    app=app,
    key_func=get_remote_address,
    default_limits=["100 per minute"]
)

# 对发送类 API 单独限制
@app.route('/api/tcp/attack', methods=['POST'])
@limiter.limit("10 per minute")  # 攻击 API 限制更严格
def api_tcp_attack():
    ...
```

**2. 可选：添加简单 Token 认证（如果以后需要多用户）**

```python
# 目前本地使用不需要，但预留接口
PT_API_TOKEN = os.environ.get('PT_API_TOKEN', '')

def require_auth():
    if not PT_API_TOKEN:
        return  # 未设置则不校验
    token = request.headers.get('X-API-Token', '')
    if token != PT_API_TOKEN:
        return jsonify({'success': False, 'message': '认证失败'}), 401
```

**3. 输入消毒**

`api_get_defaults` 和 `api_assemble` 的输入目前基本信任前端，需要加一层长度限制和类型检查，防止超大 JSON 导致内存问题。

### 2.6 车载协议专用增强（长期方向）

如果目标是**车载协议测试工具**，以下功能值得考虑：

| 功能 | 优先级 | 说明 |
|------|--------|------|
| UDS over DoIP | 高 | DoIP Payload 支持 UDS 诊断请求（0x10/0x11/0x27/0x31/0x34/0x36/0x37） |
| SOME/IP-SD 完整实现 | 中 | 服务发现的消息格式（Offer/StopOffer/Subscribe/SubscribeEventgroup） |
| CAN FD 帧构造 | 中 | 通过 SocketCAN 或 PCAN 发送 CAN FD 帧（需要额外硬件接口） |
| 诊断会话状态机 | 中 | 跟踪 UDS 会话状态（Default/Extended/Programming），自动处理 0x50/0x7F 响应 |
| 测试用例模板 | 低 | 预置常见 fuzz 模板（如边界值、长度异常、类型混淆） |
| 报文捕获联动 | 低 | 和 `capture_manager` 打通，发送后立即抓包验证 |
